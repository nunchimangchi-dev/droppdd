## What droppdd is

An aggressive fitness/coaching web app: keto, one-meal-a-day (OMAD), guided
workouts, and (eventually) AI-assisted meal planning. Tone is confident and
high-intensity — not a soft wellness/spa aesthetic.

## What to build

A full app shell with real placeholder content, no backend:

1. **Persistent layout** — nav (Dashboard, Workouts, Meals, Progress) plus a
   droppdd wordmark/logo treatment. Responsive (usable at phone width — this
   is meant to be used mid-workout on a phone). Keep the existing light/dark
   `prefers-color-scheme` pattern already started in `globals.css`, don't
   rip it out.
2. **Dashboard page (`/`)** — today's snapshot: OMAD window/status, a
   workout-of-the-day card, a couple of key stats (streak, weight trend).
   Hardcoded/mock data.
3. **Workouts page (`/workouts`)** — a list of guided workouts (mock data:
   name, duration, intensity, a few exercises each) and at least one detail
   view/page for a single workout.
4. **Meals page (`/meals`)** — keto/OMAD meal ideas as mock data. Include one
   clearly-labeled "AI meal planning — coming soon" card/section. Do **not**
   call any AI API or implement real meal generation — that's a deliberate
   follow-up decision, not yours to make here.
5. **Progress page (`/progress`)** — weight/streak history. Simple/static
   visualization is fine (a basic CSS/SVG bar or line treatment); don't pull
   in a charting library for this pass.

All data lives in a typed mock-data module (e.g. `src/lib/mock-data.ts`) —
no database, no API routes, no auth, no external network calls of any kind.
Set real `metadata` (title/description) in the root layout — the current
title is still the default "Create Next App".
